# Hero case — Level 23 "too hot" during chiller plant drift

One case carries the whole demo. Every number below is synthetic and reproducible: the chiller series
comes from `data/generate_synthetic.py` with a fixed RNG seed, and the derived figures are computed by
`backend/app/services/analytics.py`.

## The situation

| | |
|---|---|
| Site | Tower K (`SGT-01`), synthetic Singapore Grade-A office, 30 floors |
| Complaint | Level 23, ACME Manufacturing — *"it's too hot in our meeting rooms this afternoon"* |
| Reported | 2026-10-02 14:40 SGT |
| Tenant | `L23-ACME`, lease comfort band 23–25 °C, **renewal due 2026-11-15** |
| Plant | water-cooled ×3, commercial tariff |
| Observed | chiller efficiency drifted **0.62 → 0.71 kW/RT** over 14 days |

`data/raw/chiller_timeseries.csv` holds 14 days × 96 intervals (1,344 readings). The generator reports
a day-1 mean of **0.6230** and a day-14 mean of **0.7062**, which the hero-case payload rounds to
**0.62** and **0.71** — the same values quoted in the PRD.

## What the pipeline does

| Step | Module | Result |
|---|---|---|
| 1. Parse | `agents/nodes.py::parse_case` | level 23, single zone, thermal = hot, drift 0.09 |
| 2. Gate | `services/gate_service.py` | **passes** — no safety, odour, illness or Legionella signal |
| 3. Context | `services/context_check.py` | **compatible** — office / water-cooled ×3 / SG commercial |
| 4. Select | `agents/nodes.py::select_pill` | `pill-energy-chiller-drift` v2 (stub, no API key) |
| 5. Compute | `services/analytics.py` | the numbers in the table below |
| 6. Card | `agents/nodes.py::assemble_card` | 3 options, ranked safest first |
| 7. Route | `agents/nodes.py::route_action` | **execute** — one option needs approval |

## The numbers (computed, never generated by the model)

```
drift        = 0.71 − 0.62          = 0.09 kW/RT   (14.5%)
excess_kw    = 0.09 × 850 RT        = 76.5 kW
excess_kwh   = 76.5 × 24 h          = 1,836 kWh
excess_sgd   = 1,836 × S$0.28       = S$514.08
weather-normalised (wet-bulb 33.1°C vs 27°C reference) = 1,593.06 kWh
```

| Lever | Recovery | kWh delta | S$ delta | Tier |
|---|---|---|---|---|
| Inspect the L23 VAV damper | 0% | **0 kWh** | S$0 | recommend |
| Re-sequence chillers | 70% | **−1,285.2 kWh** | −S$359.86 | execute with approval |
| Lower the building-wide setpoint | −35% | **+642.6 kWh** | +S$179.93 | escalate (never_do) |

The third row is the point of the whole product: the instinctive fix **wastes 642.6 kWh** and is
flagged on the card as `Blocked by pill policy (never_do); Increases plant energy by 642.6 kWh`.

## What the card shows

- Options ordered **recommend → execute-with-approval → escalate**.
- Every option cites **pill version v2** and the excerpt behind it (`ex-4`, `ex-6`, `ex-7`).
- The **renewal flag is set** (lease due within 180 days) on all three options.
- `requires_approval = true` — nothing is issued until the Asset Operations Manager approves, and
  nothing writes to the BMS.
- `generated_by = stub`, proving the model is optional.

## Reproduce it

```bash
# without a database (unit + integration level)
cd backend && ./.venv/Scripts/python.exe -m pytest tests/test_seed_hero_case.py -v

# with the stack running
docker compose up -d db
cd backend && python -m uvicorn app.main:app --reload --port 8000
curl -s http://localhost:8000/api/v1/demo/hero-case > /tmp/hero.json
curl -s -X POST -H "X-Role: aom" -H "Content-Type: application/json" \
  -d @/tmp/hero.json http://localhost:8000/api/v1/cases | python -m json.tool
```

## The three exits (all tested)

| Case | Trigger | Route |
|---|---|---|
| **Escalate** | *"Strong chemical odour on level 23"* | `escalate` — leaves the AI path **before any model call** |
| **Blocked** | Same pill applied at Tower B (`air_cooled_2x`) | `blocked` — pending local reviewer sign-off |
| **No match** | No approved candidate pill | `escalate` — the case goes to a human |

## The governance loop (step 4 of the demo)

Mr Lim proposes **v1.3**: *"allow +0.5 °C during peak tariff hours"*. In the seed, v1.3 carries
`eval_status = 'failed'` with a score of 0.71. Approving it is **rejected by the service** before the
reviewer even sees it:

> `Version 3 has not passed its eval run and cannot be approved (FR-10).`

The reviewer rolls back to v1.2 and the diff and audit entry are shown.
